## 關鍵技術決策

1. **文案值不需要設計判斷，直接依規格表格逐字替換。**
   理由：規格已用「現況 → 改為」對照表逐一列出全部 4 處目標文字的
   確切新值，無需求解讀或產品決策空間；設計階段唯一要交代的是「每處
   文字實際存在於哪個檔案的哪個角色」，避免 developer 需要自行判斷。

2. **上傳頁 2 處（line 225 拖放文字、line 242 隱私說明）為前端靜態
   HTML 字面值，直接改字串即可，無需經過後端。**
   理由：`src/frontend/index.html` 這兩處是頁面載入時就固定顯示的
   靜態文字，不經任何 API 動態帶入，屬於最單純的字面值替換。

3. **處理中頁 3 種文案來源不同，需分開處理：**
   - `src/transcribe.py` line 59（`update_progress(..., "準備送交
     AssemblyAI...")`，15% 進度點）與 line 72（`message="已送交
     AssemblyAI，等待轉錄完成..."`，20% 進度點）是**後端動態訊息**，
     經由 `/transcribe` 回應的 `message` 欄位傳給前端、渲染於
     `#progress-message`；改字串需修改 Python 原始碼中的字面值，
     行為（進度百分比、階段名稱 `stage`）不變。
   - `src/frontend/index.html` line 267（語音轉文字階段說明）與
     line 274（AI 整理階段說明）是**前端靜態文字**（`.stage-msg`
     元素的固定內容，非後端動態帶入），與上述後端訊息互相獨立，
     兩者不可混淆修改位置。
   理由：明確區分「後端動態訊息字串」與「前端靜態顯示文字」兩種來源，
   避免 developer 誤以為 4 處全在同一個檔案，或誤改到用來判斷階段邏輯
   的 `stage`/`progress` 值（規格明確要求商業邏輯不變）。
