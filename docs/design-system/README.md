# 會議紀錄系統設計系統

一套用於「會議錄音轉紀錄系統」（及其後台管理、歷史紀錄等所有頁面）的視覺與元件規範。目的是讓任何人或任何 AI 在調整既有畫面、或開發全新頁面時，都能延續同一套外觀與互動邏輯，不必每次重新描述配色與字體規則。

## 設計原則

1. **灰階為主，不用強調色。** 全站不使用飽和色；層級靠明度（深淺）與留白區分，不靠色相。
2. **無襯線字體。** 標題與內文一律使用無襯線字體；技術性資料（Job ID、時間戳記）使用等寬字，與一般文字明確區分。
3. **不使用裝飾性圖示。** 介面上不出現裝飾用 icon；需要視覺記號時，優先用文字標籤或既有符號（例如「+」）。
4. **狀態提示與可操作元件要分開。** 像「未提及可手動填寫」「雙擊編輯」這類提示文字，樣式必須與按鈕明確不同，避免使用者誤觸。
5. **RWD 是預設需求，不是額外加項。** 每個元件在制定時就要同時想好桌面與手機（<480px）版本，手機版不得出現跑版、文字擠壓或觸控熱區過小的狀況。
6. **元素皆為可存取（Accessible）元件。** 按鈕用 `<button>`、連結用 `<a href>`、欄位一律搭配 `<label>`，鍵盤可操作、有清楚的 focus 樣式。

## 色彩

全站僅使用一組灰階色階，如下（完整清單與用途說明見 `tokens.json` / Tokens 頁）：

| 色票 | 用途 |
| --- | --- |
| `bg` | 頁面背景 |
| `surface` | 卡片、輸入框背景 |
| `border` / `border-strong` | 兩階邊框，分隔線用淺、控制項邊框用深 |
| `text-primary` / `text-secondary` / `text-placeholder` | 三階文字 |
| `ink-100`〜`ink-400` | 主色的四種深淺，用在頁首、主要按鈕、目前分頁；預設 `ink-100`，可依品牌調整選用其他深淺，但同一頁面只能選一種 |
| `badge-bg` / `badge-border` / `badge-text` | 狀態標籤專用，刻意做得比按鈕更「安靜」 |
| `focus-ring` | 鍵盤焦點外框，固定使用 `ink-100`，不隨主色深淺調整 |

**規則：** 新增任何顏色前，先確認 tokens 裡是否已有對應用途的色票；不足時才擴充色階，且新色票必須維持灰階（不得引入色相）。

## 字體

- **中文／英數內文：** `type.families.sans`（Noto Sans TC + 系統字型後援），涵蓋 Chrome、Safari、iOS Safari。
- **技術性資料：** `type.families.mono`（JetBrains Mono + 系統等寬字後援），僅用於 Job ID、逐字稿時間戳記等機器產生的資料。
- **一律不使用襯線字體。**
- 字級／字重對照見 `tokens.json` 的 `type.groups`（Heading／Body／Mono 三組，各自有桌面與手機兩種尺寸）。新頁面的標題、內文、標籤、按鈕文字都應對應到既有的字型樣式，不另外定義新字級。

## 間距與版面

- 8px 為基準的間距尺（`space-1` 至 `space-8`），任何內距、間隔都應對應到既有間距 token，不使用任意數值。
- 圓角只有三種：按鈕／輸入框（`radius-sm`）、卡片（`radius-md`）、標籤（`radius-pill`）。
- 桌面版內容最大寬度 `container-max`（1200px），置中並保留 `space-7`（40px）左右邊界。
- 斷點：`breakpoint-mobile`（480px）以下套用手機版樣式；480px 以上維持桌面版排版（本系統不特別定義平板中間態，桌面版排版應自然折行）。

## RWD 規則（給 AI／開發者的具體規格）

| 項目 | 桌面（≥480px） | 手機（<480px） |
| --- | --- | --- |
| 頁首 | 單列，左側標題＋副標，右側導覽連結／帳號／登出，高度 `header-h-desktop` | 拆兩列：第一列僅標題＋登出，第二列為可橫向捲動的次要導覽（其餘連結、帳號信箱），高度 `header-h-mobile` |
| 工具列（多個操作按鈕／欄位並排時） | 依內容並排，超出時允許換行（`flex-wrap`） | 一律改為垂直堆疊，每個控制項全寬 |
| 多欄位表單（如日期／時間／地點） | 多欄 grid 並排 | 收成單欄，逐一往下堆疊 |
| 按鈕／輸入框高度 | `control-h-desktop`（40px） | `control-h-mobile`（44px），符合最小觸控熱區 |
| 卡片內距 | `space-6`（32px） | `space-5`（24px） |
| Job ID 等長字串 | 正常顯示 | 加上 `word-break: break-all`，避免撐破版面 |

任何新頁面／新元件，只要出現「多個控制項並排」或「多欄資料」，都必須先設計手機版的堆疊邏輯，而不是等畫面做完才回頭修。

## 元件

本系統目前收錄以下元件，各自的 README 說明用途、規則與範例，`preview.html` 提供即時預覽：

- **Button** — 主要／次要／文字三種按鈕
- **Input** — 文字輸入框、下拉選單，含 label 與 focus 樣式
- **Badge** — 狀態提示標籤（非按鈕）
- **Tabs** — 頁面內分頁切換
- **Card** — 內容卡片容器
- **Header** — 頁首（含桌面／手機兩種版型說明）

新頁面若需要清單、表格、彈窗等目前尚未收錄的元件，請先依本文件的色彩／字體／間距／RWD 規則自行組合，再回頭把定案的樣式補進本系統，讓下一次開發可以直接複用。

## 給 AI 的使用說明

調整既有頁面或設計新頁面時：

1. 先讀本文件與 `tokens.json`，取得色彩、字體、間距、圓角的實際數值，不要自行估計或使用訓練資料中的預設值（例如不要用 Inter、不要用藍色系）。
2. 需要按鈕、輸入框、標籤、分頁、卡片、頁首時，讀對應元件的 README 與 preview，依現有樣式套用，不重新設計外觀。
3. 每個新畫面都必須同時產出桌面版與手機版（<480px）配置，並套用「RWD 規則」表格中的對應規格。
4. 若需求超出目前收錄的色彩／字級／間距，先在本文件與 `tokens.json` 擴充對應 token，再套用到畫面上，避免又出現一次性、無法追蹤的樣式數值。
